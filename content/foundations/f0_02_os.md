@@text
The **operating system** (OS) manages the hardware and runs programs: it decides which program gets the CPU, gives each one its own memory, talks to disks and networks through **drivers**, and keeps users from reading each other's files.

| OS | Where you'll meet it |
|---|---|
| **Windows** 11 / Windows Server | most office PCs, Active Directory, many company servers |
| **Linux** (Ubuntu, Red Hat, Debian, Amazon Linux) | most servers, the cloud, containers, network devices |
| **macOS** | designers, developers, many startups |
| **iOS / Android** | company phones, managed with MDM |
| **ChromeOS** | schools, some call centres |

## Processes, services and users

- A **process** is a running program. Each has an ID (PID), memory, and an owner.
- A **service** (Windows) or **daemon** (Linux) runs in the background without anyone logged in: the print spooler, a web server, an antivirus.
- **User accounts** and **permissions** decide who may do what. Normal work happens as a normal user; changing the system needs **administrator** (Windows, confirmed through UAC) or **root** (Linux, through `sudo`). Running everything as admin is how one bad click becomes a company-wide incident.

## File systems

A **file system** organizes a disk into files and folders.

| File system | Used by | Notes |
|---|---|---|
| **NTFS** | Windows | permissions, encryption (EFS), large files |
| **FAT32** | USB sticks, old devices | works everywhere; max **4 GB** per file |
| **exFAT** | USB drives, SD cards | works on Windows and macOS, big files |
| **ext4**, **XFS** | Linux | permissions, journaling |
| **APFS** | macOS | snapshots, encryption |

Paths look different: `C:\Users\ana\Documents\report.docx` on Windows, `/home/ana/report.txt` on Linux and macOS (`/` is the **root** of everything).

## How a computer starts

1. **Power on**: the firmware (**UEFI**, older machines BIOS) runs **POST**, a quick hardware check. Beeps or no display at this point mean hardware.
2. UEFI finds a boot disk (the **boot order**) and starts the **boot loader** (Windows Boot Manager, GRUB on Linux).
3. The boot loader loads the OS **kernel**, which starts drivers and services.
4. You get a login screen.

Knowing these steps tells you where a problem is: no lights at all → power; beeps → hardware; "no boot device found" → disk or boot order; a crash after the logo → drivers, updates or a damaged OS. **Secure Boot** (a UEFI feature) only starts signed boot loaders, which stops boot-level malware; Windows 11 also requires a **TPM 2.0** chip, which stores encryption keys for BitLocker.

## Updates and drivers

Most security breaches use known holes that a patch already fixed. Companies **patch** on a schedule (Microsoft's "Patch Tuesday" is the second Tuesday of each month), test first on a few machines, and keep a way to roll back. A **driver** is the small program that lets the OS use a piece of hardware. A bad driver update is a classic cause of "it broke after the update".

@@quiz
A user needs to copy a 6 GB video to a USB stick, and Windows says the file is too large, although the stick has 32 GB free. Why?
* The stick is formatted FAT32, which allows at most 4 GB per file
- The stick is broken
- Videos can't be copied to USB
- NTFS can't be used on USB sticks
? Reformat it as exFAT (or NTFS for Windows-only use). Formatting erases the stick, so copy anything on it first.

@@quiz
What does Secure Boot do?
* Lets the firmware start only boot loaders that are digitally signed
- Encrypts the disk

? It blocks rootkits that try to load before the OS. Disk encryption is BitLocker (with the TPM).
