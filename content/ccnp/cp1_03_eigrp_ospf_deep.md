@@text
ENARSI expects you to calculate and troubleshoot interior routing, not just configure it. Why is a route missing from an OSPF stub area? Why doesn't EIGRP load-balance over the slower link? Why did the "wrong" router become DR? This lesson covers the EIGRP composite metric, feasible successors and unequal-cost load balancing, then OSPF cost, LSA types, area types and DR/BDR election.

## EIGRP metric

With the default K values (K1 = K3 = 1, K2 = K4 = K5 = 0), the classic metric is:

**metric = 256 × (10⁷ / minimum bandwidth in kbps + total delay in tens of microseconds)**

- Bandwidth: the **slowest** link on the path (integer division). Delay: the **sum** of outgoing interface delays.
- Typical values: GigabitEthernet bandwidth 1,000,000 kbps, delay 10 µs; FastEthernet 100,000 kbps, 100 µs; serial T1 1,544 kbps, 20,000 µs.
- Named mode uses **wide metrics** (64-bit, picoseconds) so fast links are distinguished; the idea is the same.
- Change path selection with **delay** (not bandwidth, which also affects other things such as QoS and EIGRP's bandwidth use).

## Successors and feasible successors

- **Feasible distance (FD)**: the best metric from this router to the destination.
- **Reported (advertised) distance (RD)**: the neighbour's own metric to the destination.
- **Successor**: the neighbour with the lowest total metric (installed in the routing table).
- **Feasibility condition**: a neighbour is a **feasible successor** if its **RD < current FD**. This guarantees a loop-free backup that can be used **immediately**, without a query.
- No feasible successor → the route goes **active** and EIGRP sends **queries**; stuck-in-active problems are limited with **stub routers** and summarisation.
- **Unequal-cost load balancing**: `variance n` installs feasible successors whose metric < n × FD (traffic shared in proportion to metric).

## OSPF cost

**cost = reference bandwidth / interface bandwidth** (minimum 1). The default reference is 100 Mbps, so FastEthernet, GigabitEthernet and 10G all cost 1: set `auto-cost reference-bandwidth 100000` (100 Gbps) consistently on all routers.

## LSA types

| Type | Name | Generated by | Scope |
|---|---|---|---|
| 1 | Router | every router | area |
| 2 | Network | DR | area |
| 3 | Summary (inter-area) | ABR | into other areas |
| 4 | ASBR summary | ABR | tells areas how to reach the ASBR |
| 5 | AS external | ASBR | whole domain (except stub areas) |
| 7 | NSSA external | ASBR in an NSSA | NSSA only; ABR translates to type 5 |

## Area types

| Area | LSAs allowed | Default route |
|---|---|---|
| Normal / backbone | 1, 2, 3, 4, 5 | no |
| **Stub** | 1, 2, 3 | type 3 default from ABR |
| **Totally stubby** (Cisco) | 1, 2 | type 3 default only |
| **NSSA** | 1, 2, 3, 7 | not automatic (configure `default-information-originate`) |
| **Totally NSSA** | 1, 2, 7 | type 3 default |

Area 0 can't be a stub. All routers in an area must agree on its stub flags or adjacencies won't form.

## DR/BDR election

On multi-access networks (Ethernet), routers elect a DR and BDR to reduce adjacencies:
1. Highest **interface priority** wins (default 1; **0 = never DR/BDR**).
2. Tie: highest **router ID**.
3. The election is **non-preemptive**: a new router with higher priority doesn't take over an existing DR; the BDR is promoted if the DR fails.

Neighbour states: Down → Init → 2-Way (DROthers stay here with each other) → ExStart → Exchange → Loading → **Full**. Stuck in ExStart/Exchange often means an **MTU mismatch**; no neighbour at all: mismatched area, hello/dead timers, subnet, authentication, or stub flag.

VARIANCE = 2
paths = {
    "R2": [(1_000_000, 10), (1_000_000, 10), (100_000, 100)],
    "R3": [(100_000, 100), (100_000, 100)],
    "R4": [(1_544, 20_000), (1_000_000, 10)],
    "R5": [(1_000_000, 10), (10_000, 1_000), (1_000_000, 10)],
}

def metric(links):
    return 256 * (10**7 // min(bw for bw, _ in links) + sum(d for _, d in links) // 10)

results = {n: (metric(links), metric(links[1:])) for n, links in paths.items()}
successor = min(results, key=lambda n: results[n][0])
fd = results[successor][0]
for n, (total, rd) in sorted(results.items(), key=lambda kv: kv[1][0]):
    if n == successor:
        role = "successor"
    elif rd < fd:
        role = "feasible successor"
    else:
        role = "not feasible (RD >= FD)"
    installed = n == successor or (rd < fd and total < VARIANCE * fd)
    print(f"{n}: metric {total:>10,} RD {rd:>10,}  {role:<24} {'installed' if installed else ''}")
print(f"FD = {fd:,}; variance {VARIANCE} installs metrics below {VARIANCE * fd:,}")

import ipaddress

segments = {
    "LAN A (new)": ([("R1", 1, "1.1.1.1"), ("R2", 1, "2.2.2.2"), ("R3", 100, "3.3.3.3"), ("R4", 0, "9.9.9.9")], None),
    "LAN B (existing DR R1)": ([("R1", 1, "1.1.1.1"), ("R2", 50, "2.2.2.2"), ("R5", 255, "5.5.5.5")], ("R1", "R2")),
}
AREA_LSAS = {"normal": {1, 2, 3, 4, 5}, "stub": {1, 2, 3}, "totally stubby": {1, 2}, "nssa": {1, 2, 3, 7}, "totally nssa": {1, 2, 7}}
DEFAULT_TYPE3 = {"stub", "totally stubby", "totally nssa"}
lsas = [(1, "router R1"), (2, "network 10.0.0.0/24"), (3, "inter-area 172.16.0.0/16"), (4, "ASBR R9"), (5, "external 0.0.0.0/0 from ISP"), (5, "external 192.168.50.0/24"), (7, "NSSA external 192.168.60.0/24")]

def elect(routers, existing):
    names = {r[0] for r in routers}
    if existing and all(e in names for e in existing):
        return existing
    eligible = sorted((r for r in routers if r[1] > 0), key=lambda r: (r[1], ipaddress.IPv4Address(r[2])), reverse=True)
    return eligible[0][0], eligible[1][0]

for name, (routers, existing) in segments.items():
    dr, bdr = elect(routers, existing)
    print(f"{name}: DR {dr}, BDR {bdr}")

for area, allowed in AREA_LSAS.items():
    received = [f"T{t} {d}" for t, d in lsas if t in allowed]
    if area in DEFAULT_TYPE3:
        received.append("T3 default route from ABR")
    print(f"{area}: types {sorted(allowed)}")
    for item in received:
        print("   " + item)
