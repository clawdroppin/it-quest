@@text
Most problems in post-production aren't creative. They're files: a drive that fills up on the second shoot day, a timeline that stutters because the footage is long-GOP H.265, a colourist opening the wrong version of the project, an archive that's missing the music. This lesson covers the plumbing that keeps a Resolve project healthy from the first card dump to the final archive.

## Planning storage

Work out storage before the shoot, not when the drive warning pops up. The formula is simple:

**GB per hour = bitrate in Mb/s × 3600 ÷ 8 ÷ 1000 ≈ bitrate × 0.45**

Rough bitrates to plan with (1080p at 29.97; UHD is about four times as much):

| Codec | Mb/s at 1080p29.97 | Typical use |
|---|---|---|
| ProRes 422 Proxy | ~45 | proxies |
| ProRes 422 LT | ~102 | light mezzanine |
| ProRes 422 | ~147 | editing, intermediates |
| ProRes 422 HQ | ~220 | masters, grading |
| DNxHR LB / SQ / HQ | lower to higher, similar range | the Windows-friendly equivalents |
| H.264/H.265 camera files | 50–150 at UHD | consumer and mirrorless cameras |

Blackmagic RAW sets size by its **constant bitrate** (3:1, 5:1, 8:1, 12:1) or **constant quality** (Q0, Q1, Q3, Q5) settings, and the camera shows remaining record time per card.

Then multiply:

- **Originals × the number of copies.** The **3-2-1 rule**: three copies, on two kinds of media, one off site. Camera cards don't count once they're reformatted.
- **Proxies** (small) and **optimized media** (bigger, if you use it).
- **Render cache**, which can grow to tens of gigabytes on an effects-heavy timeline.
- **Headroom**: drives slow down and fill up surprises; plan for 20% free.

## Getting media in safely

- **Clone Tool** (Media page): copies a card to one or more destinations with **checksum verification** (MD5, xxHash and others) and keeps a log. Use it, or a dedicated offload app, rather than drag-and-drop in the file browser, which doesn't verify anything.
- Name folders consistently: `PROJECT/01_MEDIA/DAY01/A_CAM/A001`. The same structure on every copy makes relinking trivial.
- **Media Management** (File → Media Management) works on a whole project, timelines or clips: **Copy**, **Move** or **Transcode**, and it can trim unused media with handles, which is how you make a lean hand-off.
- **Relinking**: when files move, clips go offline (red). Right-click → **Relink Selected Clips** or **Relink Media** and point Resolve at the new top folder; it searches below it by name and timecode.

## Proxies, optimized media and the render cache

Long-GOP codecs (H.264, H.265) store most frames as differences from others, so decoding them in real time, especially in reverse or with effects, is hard work. Resolve offers three ways to keep playback smooth:

- **Proxy media**: separate, smaller files (for example half resolution ProRes Proxy or DNxHR LB) linked to the originals. Generate them in Resolve or with the **Blackmagic Proxy Generator**, which watches folders and writes proxies into a `Proxy` subfolder that Resolve picks up automatically. Toggle with **Playback → Use Proxy Media if Available**. Proxies are portable: you can send them to a remote editor while the originals stay in the office. **Deliver always renders from the originals** unless you choose otherwise.
- **Optimized media**: similar copies that Resolve manages internally in the cache folder. They're tied to the project and less portable than proxies.
- **Render cache**: caches *the result of effects* (noise reduction, Fusion comps, heavy grades), not the source. **Smart** caching picks what to cache automatically, and **User** caching only caches what you mark. Cached clips show a blue line above them in the timeline; red means not cached yet.

Rule of thumb: proxies for heavy *sources*, render cache for heavy *effects*.

## Organising the Media Pool

- **Bins** are folders you fill by hand: by day, by camera, by scene.
- **Smart Bins** fill themselves from **rules** on metadata: "Keywords contain *drone*", "Camera # is *B*", "Duration greater than 00:00:30:00". Rules can be combined with **all** (AND) or **any** (OR), and nested. A clip can appear in several Smart Bins at once; deleting it from a Smart Bin doesn't delete it from the project.
- **Metadata** is what makes Smart Bins work: scene, shot, take, good-take flags, keywords, comments, camera and lens data. Some comes from the camera and some you add in the **Metadata** panel. Automatic Smart Bins can be generated by scene, shot, keyword and people (face detection, in Studio).
- **Power Bins** are shared across every project in the database: logos, lower thirds, sound effects.
- Colour-code clips and use **flags** and **markers**; Smart Bins can filter on those too.

## Projects, databases and libraries

Resolve stores projects in a **project library** (older versions call it a database):

- **Local** library: a folder on your disk. Simple and fast; one user.
- **Network** library: a PostgreSQL server on your network that several Resolve Studio workstations share.
- **Blackmagic Cloud** library: hosted by Blackmagic, so people in different places can open the same project. Media isn't uploaded with the project: each person needs the media locally (or proxies), and **Blackmagic Cloud Storage** or Dropbox sync can move it.

**Multi-user collaboration** (Studio for network libraries; available on Blackmagic Cloud too) lets an editor, a colourist and an audio engineer open the same project at once:

- **Bin locking**: the first person to open a bin for editing owns it; others see it read-only until it's released.
- A colourist grades a timeline while the editor keeps cutting; when the editor makes changes, the colourist sees an alert and can **compare timelines** and accept the changes.
- **Chat** and timecoded **markers** keep the conversation in the project.

## Backups and archives

- **Project backups** (Preferences → User → Project Save and Load): Resolve saves timed backups in rotation (every few minutes, hourly, daily) so a corrupted save or a bad decision isn't fatal. **Live save** writes every change immediately.
- **Export Project** (`.drp`): the project file only, small, for sending a timeline or keeping versions.
- **Export Project Archive** (`.dra`): a folder with the project **and its media**, optionally with render cache and proxies. This is the hand-off and the long-term archive.
- A **library backup** exports a whole library; do it before upgrading Resolve, because a library upgraded to a new version can't be opened by an older one.
- Archive **everything the project needs**: originals (or the trimmed media), the `.dra`, fonts, LUTs, Fusion macros, music licences, the final masters and a short `README` explaining what's where. Then check that the archive actually opens on another machine.

## A workflow that holds up

1. Plan storage and naming before the shoot.
2. Offload with checksum verification to two drives.
3. Create proxies with the Proxy Generator while you log metadata.
4. Build Smart Bins from that metadata and edit on proxies.
5. Collaborate through a shared library with bin locking.
6. Render from the originals; keep project backups on.
7. Archive with Media Management and a `.dra`, then test the restore.

clips = [

smart_bins = {
    "Interviews": ("all", [("keywords", "contains", "interview")]),
    "Usable drone": ("all", [("camera", "is", "drone"), ("duration", "greater than", 10)]),
    "Selects": ("any", [("flag", "is", "green"), ("keywords", "contains", "sunset")]),
    "Scene 12 B-roll": ("all", [("scene", "is", "12"), ("camera", "is", "B")]),
}

def rule_matches(clip, rule):
    field, op, value = rule
    actual = clip[field]
    if op == "is":
        return actual == value
    if op == "contains":
        return str(value).lower() in str(actual).lower()
    if op == "greater than":
        return actual > value
    raise ValueError(f"unknown operator {op}")

def in_bin(clip, mode, rules):
    results = [rule_matches(clip, r) for r in rules]
    return all(results) if mode == "all" else any(results)

placed = set()
for bin_name, (mode, rules) in smart_bins.items():
    members = [c["name"] for c in clips if in_bin(c, mode, rules)]
    placed.update(members)
    print(f"{bin_name:<16} ({mode}): {', '.join(members) if members else '(empty)'}")
print("not in any Smart Bin:", ", ".join(c["name"] for c in clips if c["name"] not in placed))
